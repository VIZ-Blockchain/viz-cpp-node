# Агент-доступ (HF15)

Аккаунт (**принципал**) может завести **агентов**: именованные публичные ключи, которым разрешено отправлять заданный список операций от его имени. Агент — не аккаунт, а запись у принципала. Собственные ключи принципала никому не передаются, агент отзывается одной операцией.

Типичные случаи: торговый бот, который ставит в прогнозных рынках; сервис, который делает выплаты переводами; ключ, который внешний сервис (например vizhub) принимает для входа и своих действий.

---

## `set_agent_permission_operation` (ID 105)

**Подпись:** `active` аккаунта `account`. До HF15 отвергается.

| Поле | Тип | Описание |
|------|-----|----------|
| `account` | `account_name_type` | Принципал |
| `agent_name` | `string` | Имя агента, уникально у принципала; `[a-z0-9_-]`, непустое |
| `agent_key` | `public_key_type` | Ключ агента; обязателен при выдаче, при отзыве не проверяется |
| `operations` | `flat_set<string>` | Wire-имена операций, которые может подписывать ключ (`transfer`, `pm_place_bet`, …) |
| `expiration` | `time_point_sec` | `1970-01-01T00:00:00` = бессрочно; время в прошлом = отзыв |
| `addons` | `flat_set<string>` | Метки для внешних сервисов (напр. `vizhub`); до 10 штук, каждая короче 64 байт, без `,`. Нода их хранит, но не толкует: в цепи они ничего не дают |
| `extensions` | `extensions_type` | Всегда `[]` |

Выдача (бот может ставить и переводить, vizhub принимает его ключ):

```json
["set_agent_permission", {
  "account": "alice",
  "agent_name": "trade-bot",
  "agent_key": "VIZ6MyX5QiXAXRZk7SYCiqpi6Mtm8UbHWDFSV8HPpt7FJyahCnc2T",
  "operations": ["pm_place_bet", "transfer"],
  "expiration": "2027-01-01T00:00:00",
  "addons": ["vizhub"],
  "extensions": []
}]
```

Агент только с addons (ключ для внешнего сервиса, без операций цепи):

```json
["set_agent_permission", {
  "account": "alice",
  "agent_name": "hub-login",
  "agent_key": "VIZ7…",
  "operations": [],
  "expiration": "1970-01-01T00:00:00",
  "addons": ["vizhub"],
  "extensions": []
}]
```

Отзыв — оба списка пусты (ключ можно передать нулевой `VIZ1111111111111111111111111111111114T1Anm`):

```json
["set_agent_permission", {
  "account": "alice", "agent_name": "trade-bot",
  "agent_key": "VIZ1111111111111111111111111111111114T1Anm",
  "operations": [], "expiration": "1970-01-01T00:00:00", "addons": [], "extensions": []
}]
```

Повторная выдача по тому же имени заменяет ключ, операции, addons и срок (смена ключа = перевыдача).

## Правила

- **Только прямые требования active/regular:** `proposal_create` и `proposal_delete` разрешены к делегированию. Агент может создать proposal с операцией вне своего списка, но создание не одобряет и не исполняет её: нужны обычные подписи требуемых аккаунтов. Удалить можно только proposal, для которого принципал — автор или требуемый участник; чужое предложение удалить нельзя. `proposal_update` запрещён: одобрение могло бы исполнить операции вне списка агента. `account_update` запрещён, поскольку его active-вариант может сменить active-ключи. Оба имени отвергаются при выдаче и исполнении (даже из старой некорректной записи). Master-требования агент не удовлетворяет. Операции только с master (`recover_account`, `change_recovery_account`, `set_account_price`, `set_subaccount_price`, `target_account_sale`), виртуальные операции, старые алиасы и выведенные в HF4 операции (`vote`, `content`, `delete_content`) отвергаются при выдаче.
- **Чувствительные разрешения:** агент с `set_agent_permission` может создать другому контролируемому ключу разрешение на `transfer` и любые другие делегируемые операции — это широкое право, не узкое администрирование. `set_withdraw_vesting_route` может перенаправлять будущие выводы; `account_create`, `validator_update` и операции управления параметрами/комитетом действуют по штатным правилам и могут иметь существенные последствия. Ограничение распространяется на имя операции, а не на сумму, получателя или параметры.
- **Общий ключ:** несколько имён одного принципала могут использовать один ключ; их действующие права складываются. Отзыв одного имени не удаляет другое.
- **Не больше 16 агентов** на принципала. Выдача сначала удаляет его истёкших агентов.
- **Когда подпись агента засчитывается:** только для прямого active/regular-требования принципала и разрешённого имени операции. Каждая операция транзакции проверяется отдельно; чужие требования нуждаются в собственных подписях. Вложенные `account_auths` и независимые `other` authority всегда обычные. Отзыв или смена ключа раньше в той же транзакции действует до следующих операций.
- **Удаление:** все агенты принципала стираются при смене master, смене active, восстановлении аккаунта, прямой продаже и закрытии аукциона. Смена только regular их не трогает. «Смена» — это **наличие** поля в `account_update`: если в операции есть `master` или `active`, агенты стираются даже при том же ключе. Клиент, который правит только regular или memo, обязан не передавать `master`/`active` (viz-php-lib `build_account_update` всегда шлёт все три — стирает).
